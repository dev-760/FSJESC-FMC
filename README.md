# FSJESC Financial Markets Club

The official platform of the **FSJESC Financial Markets Club** (FSJESC FMC) at the
Faculté des Sciences Juridiques, Économiques et Sociales de Casablanca — a
student-led environment for learning, researching and simulating financial markets.

> **SIMULATED MARKET — Educational environment. No real money.**
> Every instrument, price, and result on this platform is fictional and generated by
> a deterministic model. Nothing here is real market data, and nothing here is
> investment advice.

_Learn financial markets. Research. Simulate. Analyze. Improve._

## Local setup

### Prerequisites

- Node.js 20.9 or newer (Node 22+ recommended)
- pnpm 9 or newer (`corepack enable`)
- Docker, for PostgreSQL — or any reachable PostgreSQL instance

### 1. Install dependencies

```bash
pnpm install
```

### 2. Configure the environment

```bash
cp .env.example .env.local
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Paste the generated value into `AUTH_SECRET` in `.env.local`, then set the
bootstrap administrator credentials. `DATABASE_URL` defaults to the local Docker
instance.

The environment is validated by a Zod schema at startup
(`src/config/env.ts`); a misconfiguration fails fast with a message naming the
offending variable rather than surfacing later as an `undefined`.

### 3. Start PostgreSQL

```bash
pnpm db:up          # db on :5432, db-test on :5433
```

### 4. Create the schema and load demo data

```bash
pnpm db:migrate     # apply migrations
pnpm db:seed        # demo users, assets, events, articles, competition
```

The seed script refuses to run with `NODE_ENV=production` unless
`SEED_DEMO=true` is set explicitly.

### 5. Run

```bash
pnpm dev
```

The application is then available at <http://localhost:3000>.

the 12-character policy). All are clearly labelled demo data.

## Architecture in one paragraph

Dependencies point inward. `src/app` and `src/components` (presentation) call
`src/application` (use-case services), which call `src/domain` and `src/simulator`
(business logic), which depend on nothing. `src/infrastructure` implements the
interfaces the inner layers declare: database, auth, market data, mail. The
trading engine and market simulator are pure TypeScript — no React, no browser
APIs, no ORM imports — so every calculation is independently unit-testable and
deterministic. The database is the single source of truth; the client is a view.

Layer boundaries are enforced mechanically: ESLint rejects a `react`, `next`, or
`drizzle-orm` import from `src/domain` or `src/simulator` (rule **N10**).

## Testing

- **Unit** — money arithmetic, order validation, execution, limit matching,
  slippage, fees, accounting, the price model. No database, no network.
- **Integration** — real PostgreSQL: order lifecycle, transaction atomicity,
  concurrent double-spend, competition isolation, event capacity.
- **Component** — Client Component rendering and keyboard interaction in jsdom.
- **End-to-end** — Playwright against a production build, desktop and mobile
  viewports.

The coverage gate requires 90% lines and branches across `src/domain/` and
`src/simulator/engine/`.

Integration tests require `TEST_DATABASE_URL` and skip with a visible notice when
it is absent, rather than reporting a pass they did not earn.

## Honesty notice

This platform does not connect to any exchange, data vendor, or broker. Prices are
produced by a deterministic model documented in
[`MARKET_SIMULATION.md`](./MARKET_SIMULATION.md). Instruments are fictional.
Statistics shown for a simulated portfolio are educational metrics and are not
personalised financial advice.
